# UI, Menu, and Tool Mechanics

## Menu & Cursor Mechanics
- **New Game Options Reset & Wall Clock UI**: Configuring `OPTION` on the Title Screen before `NEW GAME` is overwritten by `StartNewGame()`; always configure `TEXT SPEED: FAST` and `BATTLE STYLE: SET` via the Start menu after arriving in the moving truck. On the bedroom Wall Clock UI, pressing `A` opens `"Is this the correct time?"` with the cursor on `>NO`; press `A, Up, A` to select `YES`.
- **Start Menu Cursor Memory**: The Start menu preserves its last-used index across openings. When `POKEMON` or `POKEDEX` is added at index 0, the stored index shifts relative to older items.
- **Button & Sleep Limits**: `press_buttons` accepts up to 100 button presses per call (up to 150 cumulative button presses per `run_code` script). Always batch repeated sequences (e.g. `["B", "sleep 700"] * 18`) into a single `tools.press_buttons()` call rather than calling `tools.press_buttons()` inside a Python `for` loop, as each separate `tools.press_buttons()` call incurs ~0.8s of IPC round-trip overhead.
- **Pokemon Summary Exit & Field Move Submenu Shift**: Takes 3 `B` presses to return from Summary to the Start menu (`Summary -> Party submenu -> Party slot list -> Start menu`) and a 4th `B` to close the Start menu. Note that any Pokemon knowing a field move (including **`SECRET POWER`**, `CUT`, etc.) has that move inserted at index 1 in the Party submenu (`0: SUMMARY, 1: SECRET POWER, 2: SWITCH, 3: ITEM, 4: CANCEL`), so selecting `SWITCH` on that Pokemon requires `Down, Down, A` instead of `Down, A`.
- **PC Item Withdrawal & Pokemon Deposit Exit**:
  - *Item Storage (`PLAYER'S PC`)*: Takes 4 `B` presses after withdrawing an item to return to the overworld (`Dismiss text -> Item list -> Item Storage submenu -> Top-level PC menu`).
  - *Pokemon Storage (`SOMEONE'S PC`)*: Stand at `(10, 2)` facing `Up` inside a Pokemon Center. It takes **5 `A` presses** (`A, sleep 1000, A, sleep 1000, A, sleep 1200, A, sleep 1200, A, sleep 800`: `Boot PC -> Select SOMEONE'S PC -> "Accessed SOMEONE'S PC." -> "POKEMON Storage System opened." -> Open menu`) to open `[>WITHDRAW POKEMON / DEPOSIT POKEMON / MOVE POKEMON / MOVE ITEMS / SEE YA!]`. Press `Down, sleep 400, A, sleep 1800` to open `DEPOSIT POKEMON` (cursor starts on Slot 1). Press `A, sleep 600, A, sleep 600, A, sleep 2000` to `STORE` the selected Pokemon in `BOX 1`. To exit `DEPOSIT/WITHDRAW POKEMON`, press `B, sleep 600, B, sleep 1500` (selects `NO` on `"Continue BOX operations?"`), then `B, sleep 1000, B, sleep 800` to log off the PC.
- **Bag Pocket Navigation & Cursor Clamping**:
  - Bag pockets (`1: ITEMS`, `2: POKE BALLS`, `3: TMs & HMs`, `4: BERRIES`, `5: KEY ITEMS`) wrap around between `ITEMS` and `KEY ITEMS`.
  - Switching through an empty pocket (`TMs & HMs` or `BERRIES`) clamps the item cursor onto `>CLOSE BAG`; since `Up` never wraps past index 0 inside a Bag pocket or Poke Mart list, pressing `Up` multiple times deterministically clamps to index 0 (and `Up, Up, Down` deterministically selects index 1).
  - Giving a held item (`GIVE`) to a Pokemon already holding an item takes **4 `A` presses** on the Party screen: `1st A` selects the slot (`"[POKEMON] is already holding one [ITEM].♥"`), `2nd A` advances to `"Would you like to switch the two items? [>YES / NO]"`, `3rd A` confirms `YES` (`"The [OLD ITEM] was taken and replaced with the [NEW ITEM]."`), and `4th A` dismisses the text and fades back to the Bag (`~1200ms`).
  - In `KEY ITEMS`, the `USE / REGISTER / CANCEL` submenu is arranged in 2 columns (`>USE` on left, `REGISTER` on right); press `A, Right, A` to register a Key Item to `Select`.
  - In `BERRIES`, berries are sorted numerically by Berry ID (`index 0: No01 CHERI BERRY`, `index 1: No03 PECHA BERRY`, `index 2: No07 ORAN BERRY`), so clamping with `Up, Up, Up` selects `CHERI BERRY`, `Up, Up, Up, Down` selects `PECHA BERRY`, and `Up, Up, Up, Down, Down` selects `ORAN BERRY`. In contrast, the `POKE BALLS` pocket (`pocket 2`) orders balls by acquisition order rather than Item ID (verified Turn 751: `0: POKE BALL`, `1: PREMIER BALL`, `2: GREAT BALL`). In the overworld, the Berry submenu is a 2-column grid (`Row 0: >CHECK TAG`; `Row 1: USE | GIVE`; `Row 2: TOSS | CANCEL`); press `A, Down, A` to `USE` a Berry or `A, Down, Right, A` to `GIVE` a Berry. **In battle, `USE` is disabled on Berries (only `>CANCEL` appears).**
- **Rare Candy Chaining, Evolution Safety & Move Replacement**:
  - **CRITICAL — Never Press `B` After Rare Candy Level-Ups**: Many Pokemon in this ROM hack have lowered evolution levels (e.g., `Bellsprout -> Weepinbell` at **Lv 16** instead of Lv 21, observed Turn 709). Pressing `B` during the ~15-second evolution animation cancels the evolution (`"Huh? [POKEMON] stopped evolving!♥"`). Never queue `B` presses immediately after a Rare Candy level-up; use only `A` presses and verify you have returned to the Bag before pressing `B`.
  - Each Rare Candy takes **6 `A` presses** when no move is learned: `1st A` selects `>RARE CANDY` (`sleep 400`), `2nd A` selects `>USE` (`sleep 1000` fade into Party), `3rd A` selects the Party slot (`sleep 2500` level-up chime + `"elevated to Lv. X"`), `4th A` opens stat deltas (`sleep 600`), `5th A` shows new total stats (`sleep 600`), and `6th A` closes the stat box and fades back to the Bag (`sleep 1400`). Learning a move into an empty slot (slots 2–4) plays a **`~3000ms` fanfare** before `"learned [MOVE]!♥"` can be dismissed with a 7th `A` press to fade back to the Bag (`~1500ms`).
  - Because `BAG -> USE` remembers `gPartyMenu.slotId`, pressing `["A", "sleep 950"]` repeatedly from `>RARE CANDY` automatically chains Rare Candies onto the currently selected slot (`Slot 1..6`) as long as no 5th-move replacement prompt triggers.
  - **8-`B` Overworld Sync Barrier**: After chaining Rare Candies on one slot, `["B", "sleep 1200"] * 8` deterministically advances any remaining stat/move-learned textboxes and backs out from Party / Bag / Start menu all the way to the overworld (`sStartMenuCursorPos = 2` `>BAG`, `ITEMS` pocket; verified Turn 909). From there, `Start, sleep 400, A, sleep 1000, Up, Up, sleep 200, A, sleep 400, A, sleep 1000, Left, sleep 200` re-opens the Party menu clamped onto `Slot 1`, allowing `Down * k` to select the next Party slot within the same script.
  - When replacing a move on a Pokemon with 4 moves, selecting the move to forget triggers **4 sequential text boxes**: `"1, 2, and... ... ... Poof!♥"` (`~2500ms`) -> `"[POKEMON] forgot how to use [MOVE].♥"` (`~1500ms`) -> `"And...♥"` (`~1200ms`) -> `"[POKEMON] learned [NEW MOVE]!"` (`~3000ms` fanfare + `A`/`B` to return to Bag). To **decline** learning a 5th move from `"However, [POKEMON] already knows four moves.♥"`, press `B, sleep 1200` (opens `"Should a move be deleted... [>YES / NO]"`), `B, sleep 1200` (selects `NO`, opening `"Stop trying to teach [MOVE]? [>YES / NO]"`), **`A, sleep 1200`** (confirms `>YES`; never press `B` here or it selects `NO` and loops infinitely!), and `B, sleep 1500` to dismiss `"[POKEMON] did not learn [MOVE].♥"` and return to the Bag.
- **Naming Screen Helper (`naming.py`) & NPC `YES / NO` Prompts**: Use `naming.get_naming_buttons(name, confirm=True, start_pos=(0, 0))` to generate exact button inputs for uppercase nicknames. Never use `B` when approaching a gift/capture nickname `YES / NO` prompt or an NPC gift `YES / NO` prompt (such as the Route 103 Old Rod Fisherman's `"Do you like to fish?"`), as `B` selects `NO`. From `"Gotcha! [POKEMON] was caught!♥"`, it takes **4 `A` presses** (`Gotcha! -> Pokedex text -> Pokedex entry -> Give a nickname [>YES]`) to open the naming screen for a new species, or **2 `A` presses** (`Gotcha! -> Give a nickname [>YES]`, `["A", "sleep 1500", "A", "sleep 2500"]`) when catching a repeat species already registered in the Pokedex; if `"Gotcha!"` was already dismissed with `B` so the screen is on `"[POKEMON]'s data was added to the POKEDEX.♥"`, it takes **3 `A` presses** (`["A", "sleep 2000", "A", "sleep 1500", "A", "sleep 2500"]`) to open the naming screen with 0 stray characters typed. When a 7th+ Pokemon is sent to the PC after nicknaming, the `"It was placed in BOX 'BOX1.'"` message on the naming screen requires **`A`** (not `B`) to dismiss.

## Overworld & Fishing Mechanics
- **NPC Sprite Coordinates**: Gen 3 NPC sprites are 32px tall (2 vertical tiles); their true collision/interaction tile is always the bottom half (feet/shadow), while their head overlaps `y - 1`.
- **Turn-in-Place Delay & Wandering NPC Detection**: When turning to face an adjacent obstacle/NPC without stepping onto a new tile, include `"sleep 300"` between the directional input and `"A"`, otherwise `"A"` fires during the 8-frame turn animation and is ignored. For wandering NPCs (such as the Route 103 Old Rod Fisherman inside the obstacle-free `x=18..21, y=9..12` grass rectangle) who can move during turn startup, step tile-by-tile in `run_code` and check `mgba.get_coordinates() == prev_pos`; a blocked interior step guarantees the player just bumped into and is facing the NPC.
- **Old Rod Timing (`Task_Fishing`)**:
  - Cast animation before the 1st dot takes ~1.5s, and each of the 3..10 dots takes ~0.33s (`3 dots = 2.5s` .. `10 dots = 4.8s`), with a ~0.55s `"Oh! A bite!"` window.
  - **Battle-Safe Multi-Cast Loop**: Chaining `Select, sleep <3300..4800>, A, sleep 1200, B, sleep 1000` across multiple casts in a single `press_buttons` call is 100% battle-safe: once a cast hooks a fish (`"A"` -> `"A POKEMON's on the hook!"` -> `"B"` starts the battle), any remaining `A` + `B` pairs harmlessly open and close the `FIGHT` menu without using a move (verified Turn 182 when hooking Lv 5 Azurill at `4500ms`).
- **Pokemon Center Healing**: Standing at `(7, 4)` facing `Up` at Nurse Joy, it takes **4 `A` presses** (`1st A` interacts, `2nd A` advances `"Welcome..."`, `3rd A` advances `"Would you like me to rest your POKEMON?"` to `>YES`, `4th A` confirms `>YES` and starts the `~5500ms` healing fanfare + `"Thank you for waiting.♥"`), followed by **4 `B` presses** (`sleep 1200` apart) and `sleep 1500` for her bow to finish her farewell dialogue, and `Down x5` to exit the Pokemon Center.
- **Poke Mart Purchasing**: Entering a Poke Mart places the player at `(3, 7)`; walk `Up x4` to `(3, 3)` and face `Left` (`sleep 300`) to speak with the clerk across the counter at `(2, 3)`. Poke Balls cost only `$10` each (`$110` for 11 + 1 bonus Premier Ball). The exact button sequence to open the `BUY` list and buy 11 Poke Balls is **6 `A` presses**: `1st A` (`sleep 800`, `"Welcome!♥"`), `2nd A` (`sleep 800`, `"How may I serve you? [>BUY]"`), `3rd A` (`sleep 1800`, fades into `BUY` list on `>POKE BALL`), `4th A` (`sleep 1000`, opens `"How many would you like? [x01]"`), `Right` (`sleep 400`, changes `x01 -> x11`), `5th A` (`sleep 1000`, `"And you wanted 11? [>YES]"`), and `6th A` (`sleep 1200`, confirms purchase). After confirming a 10+ ball purchase, it takes **2 `B` presses** (`Thank you -> Premier Ball`) to return to the `BUY` list for another batch, or **6 `B` presses** (`Thank you -> Premier Ball -> BUY list -> Anything else -> QUIT -> Please come again!`) to return to overworld control, and `Down x5` from `(3, 3)` exits the Mart.
- **Party Menu Fade-In & Navigation**:
  - Opening the Party menu (`Start -> POKEMON` or `BAG -> USE`) takes ~800ms to fade in; directional inputs sent within 300ms of opening are ignored during the fade-in.
  - `BAG -> USE` remembers the last active Party `slotId` (including slots selected during a prior `GIVE`), whereas `Start -> POKEMON` and `BAG -> GIVE` always open at `slotId = 0` (Slot 1).
  - `Down` steps sequentially (`Slot 1 -> Slot 2 -> ... -> Last Slot -> CANCEL -> Slot 1`), `Up` steps in reverse (`Slot 1 -> CANCEL -> Last Slot`), and `Left` from any slot (`Slots 1..6`) deterministically clamps the cursor onto `Slot 1` (`slotId = 0`).
- **Battle Menu Action Cursor, Move Clamping, `Select` Move-Swapping & Bag/Battle Exit Timing**: At the start of every new battle turn (`What will [POKEMON] do?`), the action cursor always resets to `>FIGHT` (top-left, index 0). It only remains on `>BAG` or `>POKEMON` if you cancel out of the Bag or Party screen with `B` during the same turn, or after a failed Poke Ball throw (`>BAG`). Note that in trainer battles, pressing `B` while `What will [POKEMON] do?` is open leaves the cursor on `>FIGHT` (verified Turn 638 frames #201–#228; in wild battles `B` moves the cursor to `>RUN`), and `Up, Right` from any position on the 2x2 action menu clamps onto `>BAG`. Inside `FIGHT`, the 2x2 move grid (`1: Top-Left`, `2: Top-Right`, `3: Bottom-Left`, `4: Bottom-Right`) resets to Slot 1 (`Top-Left`) when a Pokemon switches in from the back row and **never wraps**, so always clamp explicitly (`Up, Left` for Slot 1, `Up, Right` for Slot 2, `Up, Left, Down` for Slot 3 [note: if Slot 4 is empty `-`, pressing `Down` from Slot 2 does nothing, so always clamp `Up, Left` before pressing `Down`!], `Down, Right` for Slot 4). Because `gMoveSelectionCursor` persists on the last-used move slot across turns as long as that Pokemon remains in battle, clamping to your desired move slot on the first turn (e.g. `A, sleep 400, Down, Left, sleep 200, A` for Slot 3) keeps the cursor on that move slot so subsequent `A, sleep 400, A` loops automatically repeat that move. In a Single Battle, the initial two-Pokemon send-out after dismissing `"[TRAINER] would like to battle!♥"` takes `~6100ms` (`use sleep 6500`, verified Turn 972 frames #51–#82), dismissing `"gained X EXP. Points!♥"` with `B` when a trainer sends out their next Pokemon takes `~4600ms` (`use sleep 5000`) before `"What will [POKEMON] do?"` opens, and selecting `SHIFT` on the Party screen takes `~9300ms` (`switch-out + send-in + opponent's turn`) before the next `"What will [POKEMON] do?"` prompt opens (use `sleep 9800`, verified Turn 768). In a Double Battle, the initial four-Pokemon send-out after dismissing `"would like to battle!♥"` takes `~6300ms` (use `sleep 6500`), and selecting `SHIFT` on the Party screen takes `~1300ms` to fade back to `"What will [PARTNER] do?"` (use `sleep 1800` before inputting the partner's move). Note that on the Double Battle target-selection screen for single-target moves (`MOVE_TARGET_SELECTED`), the **top row (`Up`)** targets the two opponents (the default target with `A` is the **top enemy HP bar / right sprite**, and pressing `Left` or `Right` switches to the **bottom enemy HP bar / left sprite**; if the targeted opponent faints earlier in the same turn, single-target moves automatically redirect to the remaining opponent), whereas pressing **`Down`** moves the target cursor onto your **own partner** (`B_POSITION_PLAYER_RIGHT` / `LEFT`, verified Turn 792 when a desynced `Down, Left, A` input targeted partner `Hermes`). Never press `Down` on the target-selection screen! Closing the Bag in battle with `B` takes `~1000ms` to fade back to the battle menu; exiting a trainer battle back to the overworld after `"got $X for winning!"` takes `~2500ms` before `Start` or movement inputs are accepted (note: if `Pay Day` was used during a trainer battle, an extra `"[PLAYER] picked up $X!♥"` textbox appears after `"got $X for winning!"` before the battle exits).
- **Berry Tree Harvesting & Auto-Refill Rule**: Interacting with a Berry Tree takes **3 `A` presses** (`Interact -> "You found N [X] BERRIES!" -> "Do you want to pick the [X] BERRIES? [>YES]"`), followed by `sleep 3500` for the fanfare and **2-3 `B` presses** (`sleep 1500` apart) to dismiss the put-away and loamy-soil messages.
  - **Auto-Refill Trigger**: The harness refills any Berry currently in the Bag (`quantity >= 1`) to 99 at the **turn boundary** in the overworld. Never consume the last copy (`x 1 -> x 0`) of a newly picked Berry before ending a turn in the overworld, or it will be removed from the Bag before auto-refilling.
  - **Loamy Soil `USE` Trap**: Selecting `USE` on a Berry in the `BERRIES` pocket while facing a soft, loamy soil patch in the overworld automatically plants the Berry into the soil and exits the Bag/Start menu to the overworld instead of opening the Party menu. Always turn away or step off the loamy soil before selecting `USE` on a Berry.
- **Overworld Item Balls**: Picking up an item ball displays **2 text boxes**: `"[PLAYER] found one [ITEM]!"` (`~2500ms` fanfare + `A`/`B`) followed by `"[PLAYER] put away the [ITEM] in the [POCKET]."` (`~1000ms` + `A`/`B`).
