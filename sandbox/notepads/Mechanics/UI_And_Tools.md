# UI, Menu, and Tool Mechanics

## Menu & Cursor Mechanics
- **New Game Options Reset & Wall Clock UI**: Configuring `OPTION` on the Title Screen before `NEW GAME` is overwritten by `StartNewGame()`; always configure `TEXT SPEED: FAST` and `BATTLE STYLE: SET` via the Start menu (`Down x3, A` before obtaining a Pokemon, since the initial Start menu is `[0: BAG, 1: PLAYER, 2: SAVE, 3: OPTION, 4: EXIT]`; note that inside `OPTION`, horizontal choices wrap around [`SLOW -> MID -> FAST -> SLOW`], so press `Right` **once** from default `MID` to select `FAST`, and wait `~800ms` after opening `OPTION` before pressing `Down x2, Right` to set `BATTLE STYLE: SET`). After `reset_game`, wait until Professor Birch's speech screen is active (`["B", "sleep 800"] * 35` advances Birch's speech to `"Are you a boy? Or are you a girl?"`, where `B` does nothing; on the first pass through the gender prompt, selecting `GIRL` prints `"All right. What's your name?♥"` before `[>NEW NAME]` appears, requiring **3 `A` presses** [`Down, sleep 300, A, sleep 1500, L, sleep 150, A, sleep 1500, L, sleep 150, A, sleep 2500`] to open the naming screen for `naming.get_naming_buttons("AURORA")`, followed by `sleep 2500, A, sleep 2000` to confirm `>YES` on `"So it's AURORA? [>YES / NO]"` before `["B", "sleep 850"] * 12 + ["sleep 6500"]` enters the moving truck, verified Turn 7230). On the bedroom Wall Clock UI (which takes 3 `A` presses from the overworld to open: `A` interacts -> `A` advances `"The clock is stopped..."` -> `A` advances `"Better set it and start it!"` + `sleep 1800` fade-in), pressing `A` opens `"Is this the correct time?"` with the cursor on `>NO`; press `A, sleep 800, Up, sleep 400, A` to select `YES`, followed by `["B", "sleep 850"] * 12 + ["sleep 2500"]` to advance Mom's 5 upstairs bedroom textboxes and wait for her to walk downstairs.
- **Start Menu Cursor Memory**: The Start menu preserves its last-used raw integer index (`sStartMenuCursorPos`) across openings (and wraps vertically between `0: POKEDEX` and `6: EXIT`). When `POKEMON` or `POKEDEX` is added at index 0, `sStartMenuCursorPos` stays at the same numeric index (so e.g. configuring `3: OPTION` before obtaining a Pokemon leaves `sStartMenuCursorPos = 3`, which becomes `3: SAVE` once `0: POKEMON` is inserted—requiring `Up, Up, A` to open `1: BAG`!—and index `1: BAG` becomes index `1: POKEMON` once `POKEDEX` is inserted at index 0, verified Turns 1732 and 7239).
- **Button & Sleep Limits, Script Timeout & Cutscene Trigger Separation**: `press_buttons` accepts up to 100 button presses per call (up to 150 cumulative button presses per `run_code` script, with a 120s script execution timeout — note that if a `run_code` script times out at 120s, any unexecuted buttons from the active `press_buttons` call remain in the emulator's input queue on the next turn, so always call `mgba.clear_buttons()` first on the turn after a timeout!). Just like consecutive `A` presses, consecutive `B` presses separated only by a `sleep` (such as `"B", "sleep 1200", "B", "sleep 800"` when closing the Bag and Start menu) can be coalesced into a single `B` press that leaves the Start menu open; always interleave `"L"` (`"B", "sleep 1000", "L", "sleep 200", "B", "sleep 800"`) when closing the Bag and Start menu to guarantee both menus close cleanly. Always batch repeated sequences (e.g. `["B", "sleep 700"] * 18`) into a single `tools.press_buttons()` call rather than calling `tools.press_buttons()` inside a Python `for` loop, as each separate `tools.press_buttons()` call incurs ~0.8s of IPC round-trip overhead. However, **always emit movement onto a cutscene/trainer/warp trigger in its own `tools.press_buttons()` call** before emitting the `A`/`B` dialogue-advancement call, because the pathfinding monitor aborts the remainder of a `press_buttons` call as soon as overworld navigation ends (e.g. when text appears or a battle starts). When a step into tall grass or a cave aborts a movement call on a wild encounter, note that **the step that triggers the wild encounter already updates `mgba.get_coordinates()` to the destination tile before the battle starts**. Therefore, never use a fixed `for btn, target in steps` list (which becomes off-by-one after a battle and executes `Down, Right` in the overworld); instead, use a coordinate-driven loop that compares `new_pos == pos` (which only holds when a wild battle is active and blocked movement) before running the flee sequence `["sleep 5000"] + ["B", "sleep 1000"] * 10 + ["Down", "Right", "sleep 200", "A", "sleep 1500", "B", "sleep 2800"]`.
- **Pokemon Summary & Pokedex Exit, and Field Move Submenu Shift**: Exiting the Pokedex (`POKEDEX` list view) takes **1 `B` press** (`B, sleep 1000`) to return to the Start menu (`0: POKEDEX`), and a 2nd `B` press closes the Start menu to the overworld. Exiting Pokemon Summary takes 3 `B` presses to return from Summary to the Start menu (`Summary -> Party submenu -> Party slot list -> Start menu`, using `sleep 1000` after the 3rd `B` for the ~800ms Party fade-out) and a 4th `B` to close the Start menu. Note that any Pokemon knowing field moves (including **`SECRET POWER`**, **`SWEET SCENT`**, **`TELEPORT`**, `CUT`, etc.) has each field move inserted above `SWITCH` in the Party submenu (`1 field move` -> `SWITCH` is at index 2 [`Down x2, A`]; `2 field moves` such as `TELEPORT` + `SECRET POWER` -> `SWITCH` is at index 3 [`Down x3, A`], verified Turn 1253).
- **PC Item Withdrawal & Pokemon Deposit Exit**:
  - *Item Storage (`PLAYER'S PC`)*: Takes 4 `B` presses after withdrawing an item to return to the overworld (`Dismiss text -> Item list -> Item Storage submenu -> Top-level PC menu`).
  - *Pokemon Storage (`SOMEONE'S PC`)*: Stand at `(10, 2)` facing `Up` inside a Pokemon Center. It takes **5 `A` presses** (`A, sleep 1000, A, sleep 1000, A, sleep 1200, A, sleep 1200, A, sleep 800`: `Boot PC -> Select SOMEONE'S PC -> "Accessed SOMEONE'S PC." -> "POKEMON Storage System opened." -> Open menu`) to open `[>WITHDRAW POKEMON / DEPOSIT POKEMON / MOVE POKEMON / MOVE ITEMS / SEE YA!]`. Press `Down, sleep 400, A, sleep 1800` to open `DEPOSIT POKEMON` (cursor starts on Slot 1). Press `A, sleep 600, A, sleep 600, A, sleep 2000` to `STORE` the selected Pokemon in `BOX 1` (note: `STORE` returns directly to the `DEPOSIT POKEMON` Party list without a `"Continue BOX operations?"` prompt and places the deposited Pokemon into the **first empty slot** of `BOX 1` starting from `(0, 0)` top-left, so when opening `WITHDRAW POKEMON` afterward, move `Right` past any newly deposited Pokemon to select an earlier boxed Pokemon, verified Turns 2363 and 4493). Inside `DEPOSIT/WITHDRAW POKEMON`, pressing `B, sleep 600, B, sleep 1500` (opening `"Continue BOX operations?"` and selecting `NO`; selecting `YES` with `A` stays inside the current screen) returns to `[WITHDRAW POKEMON / >DEPOSIT POKEMON / ...]`, from which `Up, sleep 400, A, sleep 1800` opens `WITHDRAW POKEMON` or `B, sleep 1000, B, sleep 800` logs off the PC.
- **Bag Pocket Navigation & Cursor Clamping**:
  - Bag pockets (`1: ITEMS`, `2: POKE BALLS`, `3: TMs & HMs`, `4: BERRIES`, `5: KEY ITEMS`) wrap around between `ITEMS` and `KEY ITEMS`.
  - Switching through an empty pocket (`TMs & HMs` or `BERRIES`) clamps the item cursor onto `>CLOSE BAG`; since `Up` never wraps past index 0 inside a Bag pocket or Poke Mart list, pressing `Up` multiple times deterministically clamps to index 0 (and `Up, Up, Down` deterministically selects index 1).
  - Giving a held item (`Start -> BAG -> GIVE`) to a Pokemon with **no** held item takes **2 `A`/`B` presses** on the Party screen (`1st A` selects the slot -> `"[POKEMON] was given the [ITEM] to hold.♥"`, `2nd A`/`B` dismisses the text and fades back to the Bag), whereas replacing an existing held item takes **4 `A` presses** on the Party screen: `1st A` selects the slot (`"[POKEMON] is already holding one [ITEM].♥"`), `2nd A` advances to `"Would you like to switch the two items? [>YES / NO]"`, `3rd A` confirms `YES` (`"The [OLD ITEM] was taken and replaced with the [NEW ITEM]."`), and `4th A` dismisses the text and fades back to the Bag (`~1200ms`). Note that when giving an item via `Start -> POKEMON -> ITEM -> GIVE` (rather than `Start -> BAG -> GIVE`), selecting the item in the Bag returns directly to the Party screen (`"[POKEMON] was given the [ITEM] to hold."`), requiring **3 `B` presses** (`B, sleep 1200, B, sleep 1500, B, sleep 800`) to return to the overworld.
  - In `KEY ITEMS`, the `USE / REGISTER / CANCEL` submenu is arranged in 2 columns (`>USE` on left, `REGISTER` on right); press `A, Right, A` to register a Key Item to `Select` (note: registering adds the `SEL` badge and stays inside `KEY ITEMS`, so press `B, sleep 1000, L, sleep 200, B, sleep 600` to close the Bag and Start menu; note that using a registered Key Item like `Old Rod` via `Select` in the overworld does NOT change `gBagPosition.pocket`, verified Turn 4720).
  - In `BERRIES`, berries are sorted numerically by Berry ID (`No01 CHERI BERRY`, `No03 PECHA BERRY`, `No06 LEPPA BERRY`, `No07 ORAN BERRY`). With the standard harvested berries on Route 102 (`PECHA BERRY` and `ORAN BERRY`), the indices are `0: PECHA BERRY` (`Up, Up, Up`) and `1: ORAN BERRY` (`Up, Up, Up, Down`); once `CHERI BERRY` is harvested on Route 104 North, the 3 berries are `0: CHERI BERRY` (`Up, Up, Up`), `1: PECHA BERRY` (`Up, Up, Up, Down`), and `2: ORAN BERRY` (`Up, Up, Up, Down, Down`) (shift `ORAN BERRY` down by 1 if `No06 LEPPA BERRY` was obtained from a wild `Cleffa`). In contrast, the `POKE BALLS` pocket (`pocket 2`) orders balls by acquisition order rather than Item ID (verified Turn 751: `0: POKE BALL`, `1: PREMIER BALL`, `2: GREAT BALL`). In the overworld, the Berry submenu is a 2-column grid (`Row 0: >CHECK TAG`; `Row 1: USE | GIVE`; `Row 2: TOSS | CANCEL`); press `A, Down, A` to `USE` a Berry or `A, Down, Right, A` to `GIVE` a Berry. **In battle, `USE` is disabled on Berries (only `>CANCEL` appears).**
- **Rare Candy Chaining, Evolution Safety & Move Replacement**:
  - **CRITICAL — Never Press `B` After Rare Candy or In-Battle Level-Ups**: Many Pokemon in this ROM hack have lowered evolution levels (e.g., `Bellsprout -> Weepinbell` at **Lv 16** instead of Lv 21, observed Turn 709; `Oddish -> Gloom` at **Lv 16** instead of Lv 21, observed Turn 1386; `Mudkip -> Marshtomp` at **Lv 16**, observed Turn 1604). Pressing `B` during the ~15-second evolution animation (either after a Rare Candy or after `"got $X for winning!♥"` at the end of a battle in which a Pokemon reached Lv 16) cancels the evolution (`"Huh? [POKEMON] stopped evolving!♥"`). Always use **`A`** (`["A", "sleep 1200"] * 10`) instead of `B` to advance end-of-battle EXP/victory text whenever a party member leveled up, or after closing the Lv 16 total stats box on a Rare Candy evolution, wait `~20.5s` using harmless `Up` taps (`"Up", "sleep 7000", "Up", "sleep 7000", "Up", "sleep 6500", "A", "sleep 2500"`) so you neither cancel the evolution nor feed an extra Rare Candy (verified Turn 1606).
  - Each Rare Candy takes **6 `A` presses** when no move is learned: `1st A` selects `>RARE CANDY` (`sleep 400`), `2nd A` selects `>USE` (`sleep 1000` fade into Party), `3rd A` selects the Party slot (`sleep 2500` level-up chime + `"elevated to Lv. X"`), `4th A` opens stat deltas (`sleep 600`), `5th A` shows new total stats (`sleep 600`), and `6th A` closes the stat box and fades back to the Bag (`sleep 1400`). Learning a move into an empty slot (slots 2–4) plays a **`~3000ms` fanfare** before `"learned [MOVE]!♥"` can be dismissed with a 7th `A` press to fade back to the Bag (`~1500ms`).
  - Because `BAG -> USE` remembers `gPartyMenu.slotId` *only from a prior `BAG -> USE` or `BAG -> GIVE` action* (inspecting a slot via `Start -> POKEMON` resets `slotId` to `0` upon exiting `POKEMON`, verified Turn 1294, and PC deposits set `slotId` to the deposited slot), you **MUST ALWAYS start with `"Left", "sleep 200"` to clamp onto `Slot 1` (`slotId = 0`) BEFORE pressing `Down * k` or `Up, Up`** on the 1st Rare Candy (pressing `Up, Up` without `Left` first steps up the right column onto `Slot 1` instead of wrapping to `Slot 6`, verified Turn 2361)!
  - **8-`B` Overworld Sync Barrier & Self-Synchronizing Per-Level Loop**: After chaining Rare Candies on one slot, `["B", "sleep 1200"] * 8` deterministically advances any remaining stat/move-learned textboxes and backs out from Party / Bag / Start menu all the way to the overworld (`sStartMenuCursorPos = 2` `>BAG`, `ITEMS` pocket; verified Turn 909). When raising a Pokemon across multiple levels where it may learn a move into an empty slot (slots 2–4) at an unknown level, ending each Rare Candy with `"A", "sleep 3500", "B", "sleep 1500", "B", "sleep 1000", "B", "sleep 800"` is 100% self-synchronizing: whether 0 moves or 1 empty-slot move was learned, all 3 `B` presses deterministically return to the Overworld (`sStartMenuCursorPos = 2` `>BAG`, `0: RARE CANDY`, and `gPartyMenu.slotId` preserved on that Party slot; verified Turn 3056). Note: if you want to return from the Bag to the Start menu (e.g. to open `POKEMON` via `Up, A`) after the 6th `A` press of a Rare Candy has already faded back to the Bag, press **`B` ONLY ONCE (`"B", "sleep 1000"`)**—pressing `B` a second time closes the Start menu to the overworld! Also note that teaching a TM into an empty move slot from `3: TMs & HMs` takes **7 `A` presses**: `1st A` selects `>TM`, `2nd A` selects `>USE` (`"Booted up a TM.♥"`), `3rd A` advances `"It contained [MOVE].♥"`, `4th A` advances to `"Teach [MOVE] to a POKEMON? [>YES]"`, `5th A` confirms `>YES` and fades into Party (`~1500ms`), `6th A` selects the Party slot (`~3500ms` fanfare), and `7th A` dismisses `"learned [MOVE]!♥"` (`~1500ms` fade back to Bag; verified Turn 4275).
  - When replacing a move on a Pokemon with 4 moves, note that on the Move Summary screen (`pokemon_summary_screen.c`), the 4 moves are a vertical 1D list (`0: Slot 1`, `1: Slot 2`, `2: Slot 3 [Down x2]`, `3: Slot 4 [Down x3]`). ## Overworld & Fishing Mechanics
- **NPC Sprite Coordinates**: Gen 3 NPC sprites are 32px tall (2 vertical tiles); their true collision/interaction tile is always the bottom half (feet/shadow), while their head overlaps `y - 1`.
- **Turn-in-Place Delay & Wandering NPC Detection**: When turning to face an adjacent obstacle/NPC without stepping onto a new tile, include `"sleep 300"` between the directional input and `"A"`, otherwise `"A"` fires during the 8-frame turn animation and is ignored. For wandering NPCs (such as the Route 103 Old Rod Fisherman inside the obstacle-free, grass-free **`x=19..20, y=8..10`** rectangle; note `(18, 11..12)` is tall grass and `(21, 11)` is an impassable shoreline corner, verified Turn 2400) who can move during turn startup, step tile-by-tile strictly within `x=19..20, y=8..10` in `run_code` and check `mgba.get_coordinates() == prev_pos`; a blocked interior step guarantees the player just bumped into and is facing the NPC.
- **Old Rod Timing (`Task_Fishing`)**:
  - `Fishing_Start` rolls uniformly between `3` and `10` dots (`(Random() % 8) + 3`), and `Fishing_CheckForBite` only runs *after* all rolled dots finish printing. Pressing `A` during `Fishing_WaitForDots` while dots (`. . . .`) are still printing immediately cancels the cast into `"Not even a nibble..."`, and `Fishing_WaitForA` gives a `~1200ms` window after `"Oh! A bite!"` appears. Cycling through **`[2500, 2900, 3300, 3700, 4100, 4500] * 2`** (`400ms` step size across `2500..4500ms`, 12 casts per `run_code` call, with zero directional buttons after the casts!) uniformly covers all dot counts inside their `1200ms` bite window (verified Turn 4873).
  - **Battle-Safe Multi-Cast Loop**: Chaining `Select, sleep <3100|3500|3900|4300|4700>, A, sleep 1200, B, sleep 1000` across multiple casts in a single `press_buttons` call is 100% battle-safe: once a cast hooks a fish (`"A"` -> `"A POKEMON's on the hook!"` -> `"B"` starts the battle), any remaining `A` + `B` pairs harmlessly open and close the `FIGHT` menu without using a move (verified Turn 2252).
- **Pokemon Center Healing**: Standing at `(7, 4)` facing `Up` at Nurse Joy (note: when walking from the PC at `(10, 2)` to Nurse Joy at `(7, 4)`, always walk **`Down x2, Left x3, Down, Up`** via `(10, 4) -> (7, 4) -> (7, 5) -> (7, 4)` so all 7 steps are walkable, avoid the NPC at `(9, 5)` in Petalburg City, and arrive at `(7, 4)` already facing `Up`; never use `Down x2, Left x3, Up` in the same `press_buttons` call, as `"Up"` from `(7, 4)` bumps the counter at `(7, 3)` and aborts the remaining button sequence!), use **5 `A` presses** spaced `1400ms` apart (`["sleep 400"] + ["A", "sleep 1400", "L", "sleep 200"] * 5 + ["sleep 6000"] + ["B", "sleep 1200", "L", "sleep 200"] * 5`) so every dialogue page finishes printing before `A` is pressed, `>YES` is guaranteed to be confirmed, the ~5.5s healing fanfare completes, and Nurse Joy's farewell closes cleanly.
- **Poke Mart Purchasing**: Entering a Poke Mart places the player at `(3, 7)`; walk `Up x4` to `(3, 3)` and face `Left` (`sleep 300`) to speak with the clerk across the counter at `(2, 3)`. Poke Balls cost only `$10` each (`$110` for 11 + 1 bonus Premier Ball). The exact button sequence to open the `BUY` list and buy 11 Poke Balls is **6 `A` presses**: `1st A` (`sleep 800`, `"Welcome!♥"`), `2nd A` (`sleep 800`, `"How may I serve you? [>BUY]"`), `3rd A` (`sleep 1800`, fades into `BUY` list on `>POKE BALL`), `4th A` (`sleep 1000`, opens `"How many would you like? [x01]"`), `Right` (`sleep 400`, changes `x01 -> x11`), `5th A` (`sleep 1000`, `"And you wanted 11? [>YES]"`), and `6th A` (`sleep 1200`, confirms purchase). After confirming a 10+ ball purchase, it takes **2 `B` presses** (`Thank you -> Premier Ball`) to return to the `BUY` list for another batch, or **6 `B` presses** (`Thank you -> Premier Ball -> BUY list -> Anything else -> QUIT -> Please come again!`) to return to overworld control, and `Down x5` from `(3, 3)` exits the Mart.
- **Party Menu Fade-In & Navigation**:
  - Opening the Party menu (`Start -> POKEMON` or `BAG -> USE`) takes ~800ms to fade in; directional inputs sent within 300ms of opening are ignored during the fade-in.
  - `BAG -> USE` remembers the last active Party `slotId` (including slots selected during a prior `GIVE`), whereas `Start -> POKEMON` and `BAG -> GIVE` always open at `slotId = 0` (Slot 1).
